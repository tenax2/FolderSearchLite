## システムの目的

Folder Search Liteは、利用者が指定したローカルフォルダを再帰走査し、ファイル名、フォルダ名、拡張子、ファイル本文から目的の項目を検索するデスクトップアプリケーションである。

検索結果は列別に絞り込みと並び替えができる。
検索条件は履歴として保存し、必要な条件をブックマークとして残せる。

## 対象範囲

システムは次の処理を対象とする。

- OS標準ダイアログによる検索ルートの選択
- ファイルシステムの再帰走査
- ファイル名、フォルダ名、拡張子の照合
- プレーンテキストとOffice Open XML文書の本文照合
- 検索の中断
- 検索結果、走査件数、読み取り失敗件数の表示
- 結果列ごとのフィルターと昇順、降順の並び替え
- 検索履歴とブックマークのローカル保存

全文索引の事前作成、複数端末間の同期、クラウド保存、古いOfficeバイナリ形式の本文解析は対象外とする。

## 利用者と外部資源

| 対象 | 役割 |
|---|---|
| 利用者 | 検索条件の入力、検索の開始と中断、結果の確認、履歴とブックマークの操作を行う。 |
| OSファイルシステム | 検索対象のフォルダ、ファイル、更新日時、サイズを提供する。 |

| ユーザー設定ディレクトリ | 履歴とブックマークのJSONファイルを保存する。 |
| OSクリップボード | 検索結果のフルパスを受け取る。 |

### フロントエンド

フロントエンドは`frontend/dist`へ直接配置した静的ファイルで構成する。
React、Vue、Viteなどのランタイムとビルド工程には依存しない。

`index.html`が画面構造、`styles.css`が表示とレスポンシブ配置、`main.js`が状態管理とバックエンド呼び出しを担当する。

### アプリケーションAPI

`App`はWailsへバインドする公開窓口である。
フォルダ選択、検索、検索中断、履歴、ブックマークの操作をフロントエンドへ公開する。

検索開始時にはキャンセル可能なコンテキストを作る。
同時に存在できる検索は1件であり、新しい検索を開始すると前の検索を停止する。

### 検索エンジン

検索エンジンは、要求を正規化してから`filepath.WalkDir`で検索ルートを逐次走査する。

読み取れない個別項目は検索全体の失敗にせず、読み取り失敗件数へ加算する。
検索ルート自体が不正な場合、コンテキストがキャンセルされた場合、走査を継続できない場合はエラーを返す。

### Office文書解析

Office文書解析は、Office Open XML形式をZIPとして開き、表示テキストを含むXMLパーツだけを読み取る。

Word、Excel、PowerPointごとに検索対象パーツを限定する。
書式、テーマ、リレーション定義は本文検索から除外する。

### 永続ストア

永続ストアは、検索履歴とブックマークをメモリへ読み込み、JSONファイルへ保存する。

更新時は一時ファイルへ書き込んでから保存先を置き換える。
プロセス内の並行操作はミューテックスで直列化する。

## 機能一覧

| ID | 機能 | 概要 |
|---|---|---|
| BF-01 | フォルダ選択 | OS標準ダイアログで検索ルートを選択する。 |
| BF-02 | 検索条件入力 | 検索語、拡張子、対象、大小区別、結果上限を指定する。 |
| BF-03 | 再帰検索 | 検索ルート配下のファイルとフォルダを走査する。 |
| BF-04 | 本文検索 | プレーンテキストと対応Office文書の本文を照合する。 |
| BF-05 | 検索中断 | 実行中検索のコンテキストをキャンセルする。 |
| BF-06 | 結果表示 | 種別、名前、相対パス、一致理由、サイズ、更新日時を表示する。 |
| BF-07 | 結果フィルター | 表示済み結果を列ごとに絞り込む。 |
| BF-08 | 結果ソート | 表示済み結果を列ごとに昇順または降順へ並べ替える。 |
| BF-09 | パスコピー | 結果のフルパスをクリップボードへコピーする。 |
| BF-10 | 履歴管理 | 成功した検索条件と結果概要を最大100件保存し、再検索する。 |
| BF-11 | ブックマーク管理 | 履歴を保存、再検索、解除する。 |

## 画面設計

### 共通ヘッダー

共通ヘッダーはアプリ名、処理状態、三つのタブを表示する。

| タブ | 内容 |
|---|---|
| 検索 | 検索条件、結果統計、結果グリッドを表示する。 |
| 履歴 | 過去の検索条件、件数、検索日時、再検索、保存を表示する。 |
| ブックマーク | 保存済み条件、再検索、解除を表示する。 |

### 検索条件

| 項目 | 入力形式 | 初期値 | 説明 |
|---|---|---|---|
| フォルダ | テキスト、参照ボタン | 空 | 検索ルートを指定する。 |
| 文字列 | テキスト | 空 | 名前と本文へ適用する検索語を指定する。 |
| 拡張子 | テキスト | 空 | カンマ、空白、セミコロン区切りで指定する。 |
| ファイル名 | チェック | 有効 | ファイル名を照合対象にする。 |
| フォルダ名 | チェック | 有効 | フォルダ名を照合対象にする。 |
| 内容 | チェック | 無効 | ファイル本文を照合対象にする。 |
| Office文書 | チェック | 有効 | 対応Office文書を本文検索に含める。 |
| 大小区別 | チェック | 無効 | 大文字と小文字を区別する。 |
| 上限 | 数値 | 500 | 1件から5000件までの結果上限を指定する。 |

### 検索結果

| 列 | 表示内容 | フィルター | ソート基準 |
|---|---|---|---|
| 種別 | ファイル、フォルダ | 選択 | 日本語表示名 |
| 名前 | 項目名 | 部分一致 | 日本語ロケール、自然数順 |
| 相対パス | ルート基準のパス、本文プレビュー | パスとプレビューの部分一致 | 相対パス |
| 一致 | 拡張子、ファイル名、フォルダ名、内容 | 選択 | 表示ラベル |
| サイズ | ファイルサイズ | 表示文字列または比較式 | バイト数 |
| 更新 | 更新年月日時分 | 部分一致 | 日時 |
| 操作 | パスのコピー | なし | なし |

サイズフィルターは、`>= 1 MB`のような比較式を受け付ける。
使用できる演算子は`<`、`<=`、`=`、`>=`、`>`であり、単位は`B`、`KB`、`MB`、`GB`、`TB`である。

## レスポンシブ設計

| 画面幅 | 配置 |
|---|---|
| 1400px超 | 検索条件を6列1行で表示する。 |
| 1081px以上1400px以下 | 入力項目を上段、チェック項目と操作を下段に表示する。 |
| 1080px以下 | ヘッダーを縦積みにし、検索条件を2列4行で表示する。 |

初期ウィンドウは1440×900、最小ウィンドウは960×640とする。
検索結果は検索パネルの残り高を使用し、領域内でスクロールする。

## データ設計

| データ | 役割 | 保存期間 |
|---|---|---|
| `SearchRequest` | 検索条件と再検索条件 | 検索中、履歴またはブックマーク保存中 |
| `SearchResponse` | 結果、統計、処理時間 | 現在画面を表示している間 |
| `SearchResult` | 一つのファイルまたはフォルダの結果 | 現在画面を表示している間 |
| `HistoryEntry` | 条件、件数、日時、ブックマーク状態 | 履歴またはブックマークから削除されるまで |
| `AppState` | 履歴とブックマークの保存単位 | アプリ終了後も保持 |

状態ファイルの既定保存先は、OSが返すユーザー設定ディレクトリ配下の`FolderSearchLite/state.json`である。
Windowsでは通常`%AppData%\FolderSearchLite\state.json`となる。

## エラー処理

| 条件 | 処理 |
|---|---|
| 検索ルート未入力 | バックエンドを呼ばず、状態欄へ入力要求を表示する。 |
| 検索ルートが存在しない、またはフォルダでない | 検索を失敗として状態欄へエラーを表示する。 |
| 個別項目を読めない | 項目を除外し、読み取り失敗件数を加算する。 |
| Office文書が破損している | 文書を除外し、読み取り失敗件数を加算する。 |
| 検索がキャンセルされた | 途中結果を履歴へ保存せず、「検索を中断しました」と表示する。 |
| 履歴保存に失敗した | 検索APIをエラーとして終了し、HistoryIDを返さない。 |
| 状態ファイルが存在しない | 空の履歴とブックマークとして開始する。 |
| クリップボードAPIを使用できない | 一時textareaと`execCommand`へフォールバックする。 |

## 非機能設計

### 性能

検索は索引を持たず、要求ごとにファイルシステムを逐次走査する。
結果上限の既定値は500件、絶対上限は5000件である。

プレーンテキストのファイルサイズと行長には上限を設けていない。
巨大な単一行は、その行をメモリへ保持する。

Office XMLの照合バッファは3000ルーンを超えると後半だけを残す。

### 信頼性

個別項目の読み取り失敗は検索全体から分離する。

検索キャンセルはコンテキストと世代番号を組み合わせる。
古い検索の終了処理は、新しい検索のキャンセル関数を解除しない。

状態保存は一時ファイルを経由して置き換える。

### セキュリティとプライバシー

検索対象の本文と検索結果を外部サービスへ送信しない。
履歴とブックマークはローカルJSONへ保存する。

状態ディレクトリは`0700`、状態ファイルは`0600`を指定して作成する。
実際のアクセス制御はOSのファイル権限実装に従う。

画面へ動的に埋め込むファイル名、パス、プレビューはHTMLエスケープする。

### 操作性とアクセシビリティ

タブは`role="tab"`、パネルは`role="tabpanel"`を持つ。
選択状態は`aria-selected`、結果の並び順は`aria-sort`へ反映する。

列フィルターには視覚表示されないラベルを設定する。
ボタンと入力要素はキーボードフォーカスを維持する。

## 制約

- 古いOfficeバイナリ形式である`.doc`、`.xls`、`.ppt`の本文は検索しない。
- バイナリ判定は先頭8000バイトのNUL文字有無による簡易判定である。
- 検索は単一プロセス内で逐次実行し、並列ファイル走査は行わない。
- 履歴は最大100件であり、ブックマークには件数上限を設けていない。
- 状態ファイルのスキーマバージョンは保持していない。
